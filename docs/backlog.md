# Product Backlog

MoSCoW priorities for the WUA Cafeteria Express prototype. Story point estimates are planning placeholders for the student team.

| ID | User story | Priority | Points |
|---|---|---|---:|
| US1 | As a student, I want to see cafeterias so I can choose where to order. | Must-have | 2 |
| US2 | As a student, I want to browse item names, categories, and prices. | Must-have | 3 |
| US3 | As a student, I want to add items and quantities to a basket. | Must-have | 3 |
| US4 | As a student, I want to submit an order using my campus ID. | Must-have | 5 |
| US5 | As a student, I want a unique order ID and total after placing an order. | Must-have | 3 |
| US6 | As a student, I want to check an order's current status. | Must-have | 3 |
| US7 | As cafeteria staff, I want to advance an order through preparation and delivery states. | Must-have | 5 |
| US8 | As a user, I want invalid inputs rejected with a useful message. | Must-have | 3 |
| US9 | As a returning user, I want to register and log in securely. | Should-have | 5 |
| US10 | As a user, I want to use the interface on a phone. | Should-have | 3 |
| US11 | As an administrator, I want to maintain cafeteria menus and availability. | Should-have | 5 |
| US12 | As a student, I want to receive status notifications. | Could-have | 5 |
| US13 | As a student, I want to filter menus by dietary preference. | Could-have | 3 |
| US14 | As a student, I want to pay using an approved cashless payment provider. | Should-have | 8 |
| US15 | As a cafeteria manager, I want order volume summaries. | Could-have | 5 |

Payment and identity features are intentionally not enabled in the classroom prototype; they need institutional approval and production safeguards.
