# Sprint Plan

**Sprint goal:** Demonstrate the core campus food-ordering journey from menu browsing through order-status lookup. Sprint duration: one week. Estimates use Fibonacci Planning Poker points.

| Task | Story points | Owner |
|---|---:|---|
| Create API and menu browsing | 3 | Team member 1 (assign name) |
| Build responsive menu interface | 3 | Team member 2 (assign name) |
| Implement order creation and totals | 5 | Team member 3 (assign name) |
| Implement order lookup and status lifecycle | 3 | Team member 3 (assign name) |
| Add automated tests and CI workflow | 5 | Team member 4 (assign name) |
| Review, integrate, and prepare demonstration | 2 | Whole team |

**Acceptance:** a valid order returns a total and ID, that order can be retrieved, status can be changed to a supported value, invalid data is rejected, tests pass, and all changes are reviewed before integration.
